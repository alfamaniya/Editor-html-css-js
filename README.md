# ویرایشگر HTML / CSS / JavaScript

ویرایشگر تحت وب برای نوشتن و آزمایش کدهای **HTML، CSS و JavaScript**، مدیریت فایل‌های یک پروژه، استفاده از کتابخانه‌های آماده، مشاهدهٔ پیش‌نمایش زنده و دریافت خروجی. برنامه با JavaScript و APIهای استاندارد مرورگر ساخته شده و برای اجرای نسخهٔ اصلی به نصب پکیج یا مرحلهٔ Build نیاز ندارد.

## قابلیت‌ها

### ویرایش و پیش‌نمایش کد

- ویرایش جداگانهٔ HTML، CSS و JavaScript با شمارهٔ خطوط و رنگ‌آمیزی نحوی.
- پیش‌نمایش زنده در `iframe` با تأخیر کوتاه پس از تغییر کد؛ محیط پیش‌نمایش با ویژگی `sandbox` از صفحهٔ اصلی ویرایشگر جدا شده است.
- تکمیل خودکار وابسته به زمینه: تگ‌ها و ویژگی‌های HTML، ویژگی‌های متناسب با تگ، مقادیر CSS، انتخابگرها، شبه‌کلاس‌ها و شبه‌عنصرها، قواعد `@`، میان‌برهای متداول CSS و پیشنهادهای JavaScript.
- پیشنهاد ادامهٔ کد بر اساس قواعد و نمونه‌های ازپیش‌تعریف‌شده؛ این قابلیت مدل هوش مصنوعی یا تحلیل‌گر کامل زبان نیست.
- تکمیل خودکار تگ‌های HTML و تورفتگی کد هنگام نوشتن، ابزار انتخاب رنگ CSS، درج سریع نمادها، تغییر اندازهٔ قلم و Undo/Redo.
- جست‌وجوی کد همراه با شمارش نتایج و حرکت بین تطبیق‌ها.

### مدیریت پروژه و کتابخانه‌ها

- فهرست فایل‌های مجازی پروژه برای ایجاد، بازنام‌گذاری، حذف و بازگردانی حذف فایل، همراه با جست‌وجو، فیلتر نوع و مرتب‌سازی/گروه‌بندی.
- مدیریت کتابخانه‌های CSS و JavaScript: افزودن کد سفارشی، انتخاب از فهرست کتابخانه‌های آماده، فعال یا غیرفعال‌کردن و حذف کتابخانه.
- دریافت برخی کتابخانه‌های آماده از CDN؛ دریافت کد از اینترنت به اتصال شبکه نیاز دارد.
- پنجرهٔ **Word Tree** برای جست‌وجو و پیمایش درخت زندهٔ پیشنهادها، فیلتر زبان، باز و بسته‌کردن شاخه‌ها و مشاهدهٔ توضیحات فارسی و نمونه‌کد.
- راهنمای درون‌برنامه‌ای به زبان انگلیسی و فارسی.

### ذخیره‌سازی و دریافت خروجی

- ذخیرهٔ خودکار پروژه، کتابخانه‌ها و برخی تنظیمات در `localStorage` مرورگر.
- نشانگر تغییرات ذخیره‌نشده و هشدار در صورت ناموفق‌بودن ذخیره.
- نگهداری نسخهٔ بازیابی از دادهٔ پروژه در برخی خطاهای خواندن یا مهاجرت داده و فراهم‌کردن امکان دریافت فایل بازیابی.
- دریافت پروژه به دو شکل: یک فایل HTML مستقل یا بسته‌ای شامل چهار فایل HTML، CSS، JavaScript و متن کتابخانه‌ها.
- نمایش زمان آخرین کامیت شاخهٔ `main` از GitHub، در صورت در دسترس بودن GitHub API.

## اجرا و پیش‌نیازها

### اجرای ویرایشگر

1. مخزن را دریافت یا Clone کنید.
2. فایل `index.html` را در مرورگر باز کنید.
3. برای ویرایش عادی، نصب Node.js یا اجرای Build لازم نیست.

نسخهٔ پایه از فایل‌های محلی مخزن استفاده می‌کند؛ بااین‌حال، نشانگر آخرین کامیت GitHub و دریافت کتابخانه‌ها از CDN به اینترنت وابسته‌اند. اگر ذخیره‌سازی مرورگر هنگام بازکردن مستقیم فایل با `file://` درست کار نکرد، برنامه را از طریق یک وب‌سرور محلی اجرا کنید.

### پیش‌نیاز آزمون و ساخت نسخهٔ تک‌فایلی

برای اجرای اسکریپت‌های کنترل و ساخت، **Node.js 20** لازم است. فرمان‌ها را از ریشهٔ مخزن اجرا کنید:

```bash
# بررسی ساختار HTML و جداکننده‌های کد در index.html
node scripts/check-index-integrity.mjs

# ساخت نسخهٔ تک‌فایلی
node scripts/build-test-editor.mjs

# اعتبارسنجی نسخهٔ تک‌فایلی تولیدشده
node scripts/check-standalone-editor.mjs

# بررسی نحو یک فایل JavaScript
node --check script.js
```

ساخت نسخهٔ تک‌فایلی، فایل `index-test-etitor.html` را از HTML، CSS و فایل‌های JavaScript منبع تولید می‌کند. برای تغییرات معمول، فایل‌های منبع را ویرایش کنید و خروجی را با فرمان ساخت دوباره تولید کنید؛ خروجی تولیدشده را به‌عنوان منبع اصلی ویرایش نکنید.

## راهنمای استفاده

### ۱. فایل‌ها و تب‌های کد

پروژهٔ اولیه شامل `index.html`، `style.css` و `script.js` است. تب‌های HTML، CSS و JavaScript برای جابه‌جایی بین زبان‌ها ویرایشگر را تغییر می‌دهند. از بخش فایل‌ها می‌توانید فایل‌های درون پروژه را ایجاد، نام‌گذاری مجدد، فیلتر، مرتب‌سازی یا حذف کنید. حذف فایل با امکان بازگردانی از اعلان برنامه همراه است.

**نکته:** این فهرست، فایل‌های مجازی ذخیره‌شده در پروژهٔ مرورگر را مدیریت می‌کند؛ فایل‌های واقعی روی دیسک را مستقیماً بازنویسی نمی‌کند. برای انتقال کد به سیستم فایل، از گزینهٔ Download خروجی بگیرید.

### ۲. پیش‌نمایش

تغییرات کد پس از وقفه‌ای کوتاه در پنل پیش‌نمایش اعمال می‌شوند. پیش‌نمایش در یک `iframe` دارای `sandbox` اجرا می‌شود؛ بنابراین برخی رفتارهایی که به دسترسی هم‌مبدأ یا دسترسی‌های محدودشدهٔ مرورگر نیاز دارند ممکن است مانند اجرای یک صفحهٔ عادی عمل نکنند.

### ۳. تکمیل خودکار و Word Tree

پیشنهادها از بانک‌های محلی و قواعد زمینه‌ای به دست می‌آیند. در پنجرهٔ **Word Tree** می‌توانید پیشنهادها را جست‌وجو کنید، زبان را فیلتر کنید، شاخه‌ها را باز یا بسته کنید و نمونه‌کد را مشاهده یا کپی کنید. این ابزار برای تسریع نوشتن است و جایگزین بررسی نحوی کامل یا Language Server نیست.

### ۴. کتابخانه‌ها

پنل Libraries برای افزودن کد CSS و JavaScript به پروژه استفاده می‌شود. کتابخانه‌های فعال در پیش‌نمایش و خروجی وارد می‌شوند. برخی گزینه‌های آماده از CDN دریافت می‌شوند؛ در محیط بدون اینترنت فقط کتابخانه‌هایی قابل استفاده‌اند که کدشان از قبل در دسترس باشد یا به‌صورت دستی اضافه شده باشد.

### ۵. خروجی گرفتن

از **Download** یکی از دو حالت را انتخاب کنید:

- **فایل HTML مستقل:** CSS، JavaScript و کتابخانه‌های فعال در یک سند HTML قرار می‌گیرند تا برای اجرای کد اصلی به فایل‌های منبع جداگانه نیاز نباشد.
- **بستهٔ چهارفایلی:** چهار فایل با نام پایهٔ انتخابی تولید می‌شود:

  1. `نام.html` — سند HTML پروژه.
  2. `نام.css` — کد CSS پروژه به‌همراه کتابخانه‌های CSS فعال.
  3. `نام.js` — کد JavaScript پروژه به‌همراه کتابخانه‌های JavaScript فعال.
  4. `نام.libs.txt` — متن کد کتابخانه‌های فعال.

این بسته آرشیو کاملی از همهٔ فایل‌ها، تصاویر یا منابع خارجی احتمالی پروژه نیست. پیش از انتقال یا انتشار، ارجاع‌های موجود در HTML و نیازهای واقعی پروژه را بررسی کنید.

## ذخیره‌سازی، بازیابی و خروجی

- پروژه و کتابخانه‌ها در `localStorage` مرورگر ذخیره می‌شوند؛ داده‌ها به همان محیط مرورگر وابسته‌اند و با پاک‌کردن داده‌های مرورگر ممکن است از بین بروند.
- ذخیره‌سازی خودکار، جایگزین تهیهٔ نسخهٔ پشتیبان نیست. برای پروژه‌های مهم مرتباً خروجی بگیرید و فایل‌های خروجی را جداگانه نگه دارید.
- اگر دادهٔ ذخیره‌شده خراب یا غیرقابل‌خواندن باشد، برنامه ممکن است هشدار بازیابی نشان دهد و امکان دریافت `project-recovery.json` را ارائه کند. این امکان فقط برای داده‌ای است که مرورگر توانسته باشد حفظ کند و تضمین بازیابی همهٔ خطاها نیست.
- فایل `github-update.js` فقط اطلاعات آخرین کامیت شاخهٔ `main` را از GitHub API می‌خواند؛ این تاریخ، شمارهٔ نسخه یا تاریخ انتشار رسمی برنامه نیست.

## آزمون‌ها و GitHub Actions

سه گردش‌کار در شاخهٔ `main` تعریف شده‌اند:

- **Build standalone test editor:** با Node.js 20 نحو فایل‌های JavaScript را بررسی می‌کند، خروجی تک‌فایلی را می‌سازد و اعتبارسنجی می‌کند؛ اگر خروجی تغییر کرده باشد، آن را با حساب GitHub Actions کامیت و Push می‌کند.
- **Check index syntax and delimiters:** در Push و Pull Requestهای مرتبط، تگ‌های `index.html`، جداکننده‌های کد و نحو JavaScript درون‌خطی را بررسی می‌کند.
- **Check index file:** ساختار ابتدایی سند و وجود فایل‌های محلی ارجاع‌شده را بررسی می‌کند.

نتایج و گزارش هر اجرا در زبانهٔ **Actions** مخزن قابل مشاهده‌اند. این بررسی‌ها خطاهای متداول را پیدا می‌کنند، اما جایگزین آزمون دستی در مرورگر، آزمون انتها‌به‌انتها، اعتبارسنج کامل HTML/CSS یا بررسی سازگاری میان مرورگرها نیستند.

## محدودیت‌های شناخته‌شده

- تکمیل خودکار مبتنی بر بانک پیشنهاد و قواعد زمینه‌ای است و درک کامل زبان، تحلیل معنایی یا قابلیت‌های یک IDE حرفه‌ای را ارائه نمی‌کند.
- فایل‌های پروژه در محیط برنامه و مرورگر نگه‌داری می‌شوند؛ فایل‌گردان به دیسک سیستم‌عامل دسترسی مستقیم ندارد و مخزن را از داخل صفحه Commit نمی‌کند.
- ذخیره‌سازی به پشتیبانی و فضای قابل‌استفادهٔ `localStorage` وابسته است. تهیهٔ خروجی و نگهداری پشتیبان مستقل توصیه می‌شود.
- نمایش آخرین کامیت و دریافت کتابخانه‌های CDN به اتصال اینترنت وابسته‌اند.
- آزمون خودکار کامل مرورگر و آزمون چندمرورگری در مخزن پیکربندی نشده‌اند؛ دانلودها، ذخیره‌سازی و رفتار پیش‌نمایش را نیز به‌صورت دستی بررسی کنید.
- در ریشهٔ مخزن فایل `LICENSE` مشاهده نشده است؛ پیش از توزیع مجدد، وضعیت مجوز پروژه را مشخص کنید.
