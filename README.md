ویرایشگر تحت وب برای نوشتن و آزمایش HTML، CSS و JavaScript با پیش‌نمایش زنده، تکمیل خودکار، مدیریت فایل‌های مجازی، کتابخانه‌ها و دریافت خروجی. نسخهٔ اصلی بدون نصب پکیج یا Build اجرا می‌شود.

## قابلیت‌ها

- ویرایش جداگانهٔ HTML، CSS و JavaScript با رنگ‌آمیزی نحوی، شمارهٔ خطوط، Undo/Redo و جست‌وجو.
- پیش‌نمایش زنده در محیط محدودشدهٔ `iframe`.
- پیشنهادهای زمینه‌ای کد و ابزار **Word Tree**؛ این امکانات جایگزین IDE یا تحلیل‌گر کامل زبان نیستند.
- **انتخاب المان از پیش‌نمایش:** ابزار اختیاری برای انتخاب المان، یافتن تگ HTML، قوانین CSS منطبق و ارجاع‌های احتمالی JavaScript؛ این تشخیص یک تحلیل‌گر کامل وابستگی‌ها نیست.
- مدیریت فایل‌های مجازی و کتابخانه‌های CSS/JavaScript.
- ذخیره‌سازی در `localStorage` و امکان دریافت نسخهٔ بازیابی در برخی خطاها.
- سکشن‌های تنظیمات شامل ظاهر برنامه، ویرایشگر کد، نمایش زنده، چیدمان محیط، ذخیره‌سازی/بازیابی و مدیریت فهرست درج سریع هستند؛ ظاهر و منطق تنظیمات در `settings.css` و `settings.js` جدا شده‌اند.
- فهرست درج سریع برای تب‌های HTML، CSS و JavaScript قابل مدیریت است؛ آیتم‌های پیش‌فرض و سفارشی در تنظیمات نمایش داده می‌شوند.
- **مدیریت کلمات پیشنهادی** امکان جست‌وجو و فیلتر بانک‌ها، دسته‌بندی‌ها و کلمات HTML/CSS/JavaScript، ویرایش متن نمایشی و متن درج‌شونده، فعال/غیرفعال‌کردن پیشنهادها، مرتب‌سازی و انتقال کلمات، و ساخت بانک سفارشی را فراهم می‌کند. تغییرات تا فشردن «ذخیره تغییرات» موقت می‌مانند و در صورت لغو، به وضعیت قبلی برمی‌گردند.
- خروجی به‌صورت یک فایل HTML مستقل یا بستهٔ چهار‌فایلی؛ ساخت فایل مستقل همچنان فقط با دستور صریح انجام می‌شود.

## اجرا

1. مخزن را Clone یا دریافت کنید.
2. فایل `index.html` را در مرورگر باز کنید.
3. اگر ذخیره‌سازی در حالت `file://` درست کار نکرد، از وب‌سرور محلی استفاده کنید.

برای اجرای بررسی‌های توسعه، **Node.js 20** لازم است. این دستورها فایل خروجی مستقل را نمی‌سازند یا تغییر نمی‌دهند:

```bash
for file in html-suggestions.js css-suggestions.js js-suggestions.js suggestion-manager.js next-word-suggestions.js preview-element-inspector.js script.js settings.js backup-restore.js word-tree.js github-update.js scripts/*.mjs tools/build-single-file.js; do
  node --check "$file" || exit 1
done

node scripts/check-index-integrity.mjs
node scripts/check-backup-restore.mjs
node scripts/check-editor-code-processing.mjs
node scripts/check-settings-dialog-keyboard.mjs
```

فایل `index-test-etitor.html` خروجی تولیدشده برای آزمایش است و منبع اصلی ویرایش محسوب نمی‌شود. ساخت، بازسازی، ثبت یا ارسال این فایل فقط پس از دستور صریح کاربر مجاز است. پس از اجازهٔ ساخت، برای اعتبارسنجی خروجی از `node scripts/check-standalone-editor.mjs` استفاده کنید.

## مدیریت کلمات پیشنهادی

- پنجرهٔ مدیریت از بخش تنظیمات باز می‌شود و درخت بانک‌ها، دسته‌بندی‌ها و کلمات را با جست‌وجو و فیلتر زبان، نوع و وضعیت نمایش می‌دهد؛ افزودن، ویرایش، حذف، مرتب‌سازی و انتقال کلمات نیز در دسترس است.
- کلمات بانک سفارشی از مسیر مشخصی مانند فهرست تگ‌های HTML، خاصیت‌های CSS، کلمات JavaScript یا فهرست مقادیر CSS به منبع واقعی تکمیل خودکار متصل می‌شوند.
- عنوان نمایشی از متن درج‌شونده جدا است؛ برای خاصیت CSS مانند `box-shadow`، نام خاصیت درج می‌شود و مقدار سایه تنها زمانی درج می‌شود که همان مقدار انتخاب شده باشد.
- تغییرات بانک‌ها تا انتخاب «ذخیره تغییرات» در حافظهٔ موقت پنجره می‌مانند؛ لغو یا بستن با تغییرات ذخیره‌نشده، وضعیت قبلی را بازمی‌گرداند. ذخیره‌سازی روی `localStorage` همان مرورگر انجام می‌شود و همگام‌سازی ابری نیست.
- اندازهٔ پنل درخت و جزئیات قابل تنظیم است؛ اندازهٔ پنل برای بازشدن‌های بعدی در همان مرورگر ذخیره می‌شود. در موبایل، پنل درخت و جزئیات از طریق دو نمای جدا جابه‌جا می‌شوند.
- اسکریپت `scripts/build-test-editor.mjs` خروجی مستقل را از منابع جداگانه می‌سازد و فایل‌های مدیریت پیشنهادها را نیز در خروجی قرار می‌دهد؛ اجرای اسکریپت به‌معنای اجازهٔ خودکار برای ساخت یا ثبت خروجی نیست.

## راهنمای کوتاه

- تب‌های HTML، CSS و JavaScript برای ویرایش کدها هستند.
- فهرست فایل‌ها، فایل‌های مجازی داخل برنامه را مدیریت می‌کند و مستقیماً فایل‌های دیسک را بازنویسی نمی‌کند.
- پیش‌نمایش پس از وقفه‌ای کوتاه به‌روز می‌شود؛ محدودیت‌های `sandbox` ممکن است بعضی قابلیت‌ها را مسدود کند.
- کتابخانه‌های آمادهٔ CDN به اینترنت نیاز دارند.
- در بخش **Download**، خروجی HTML مستقل یا بسته‌ای شامل `نام.html`، `نام.css`، `نام.js` و `نام.libs.txt` دریافت کنید.

## ذخیره‌سازی و محدودیت‌ها

- داده‌های پروژه در `localStorage` همان مرورگر ذخیره می‌شوند و ممکن است با پاک‌کردن داده‌های مرورگر از بین بروند؛ از پروژه‌های مهم پشتیبان بگیرید.
- نمایش آخرین کامیت و دریافت کتابخانه از CDN به اینترنت وابسته است.
- داده‌های مدیریت پیشنهادها و اندازهٔ پنل در `localStorage` همین مرورگر ذخیره می‌شوند؛ پاک‌کردن داده‌های مرورگر آن‌ها را حذف می‌کند.
- فایل `index-test-etitor.html` ممکن است از آخرین منابع عقب‌تر باشد؛ این فایل به‌صورت خودکار به‌روزرسانی نمی‌شود و هرگونه بازسازی آن نیازمند دستور صریح کاربر است.
- آزمون‌های ایستا جایگزین بررسی دستی پیش‌نمایش، ذخیره‌سازی و دانلود در مرورگر نیستند.

| `index-test-etitor.html` | خروجی تک‌فایلی تولیدشده برای آزمایش |

## GitHub Actions و آزمون‌ها

- **Build standalone test editor:** این Workflow فقط با اجرای دستی و ورودی تأیید `confirm_build=true` اجرا می‌شود. اجرای آن خروجی مستقل را بازسازی می‌کند و در صورت تغییر، فایل را به‌صورت خودکار کامیت و ارسال می‌کند؛ بدون دستور صریح کاربر Workflow یا اسکریپت ساخت را اجرا نکنید.
- **Check index syntax and delimiters:** ساختار تگ‌ها، جداکننده‌ها و نحو JavaScript درون‌خطی را بررسی می‌کند.
- **Check index file:** ساختار پایهٔ HTML، ارجاع‌های محلی، پردازش پیست، مدیریت صفحه‌کلید دیالوگ‌های تو‌در‌تو و نحو JavaScript منابع اصلی را بررسی می‌کند.

گزارش اجراها در زبانهٔ **Actions** مخزن قرار دارد. نام `index-test-etitor.html` مطابق نام فعلی پروژه است و اسکریپت‌های ساخت به آن وابسته‌اند.

## پشتیبان‌گیری و بازیابی

- از بخش «پشتیبان‌گیری و بازیابی» در تنظیمات، قسمت‌های دلخواه را انتخاب و فایل JSON با پسوند .editor-backup.json دریافت کنید. دادهٔ پروژه از وضعیت زندهٔ ویرایشگر خوانده می‌شود تا تغییراتی که هنوز autosave نشده‌اند از قلم نیفتند.
- قالب فایل شناسهٔ editor-backup و فیلد schemaVersion برابر ۱ دارد. بخش‌ها مستقل‌اند: تنظیمات و ترجیحات محیط، پروژه و فایل‌های مجازی، کتابخانه‌های سفارشی، دادهٔ ذخیره‌شدهٔ مدیریت بانک‌های کلمات، و درج‌های سفارشی یا تغییرات آیتم‌های پیش‌فرض.
- فایل‌های اجرایی برنامه و بانک‌های ثابت به‌عنوان فایل منبع جداگانه پشتیبان نمی‌شوند. مدل فعلی مدیریت کلمات یک snapshot از بانک‌های قابل ویرایش ذخیره می‌کند؛ بنابراین اگر این snapshot در مرورگر وجود داشته باشد، همان دادهٔ ذخیره‌شده برای حفظ سازگاری پشتیبان می‌شود و ممکن است بخشی از بانک‌های پایه را نیز در بر داشته باشد.
- هنگام بازیابی، قالب، نسخه، تاریخ، نوع داده‌ها، اندازه، تعداد آیتم‌ها، مقادیر تنظیمات، شناسه‌های فایل و پیوند فایل فعال بررسی می‌شوند. متن ورودی به‌عنوان داده تلقی می‌شود، اجرا نمی‌شود و در پیش‌نمایش با textContent نمایش داده می‌شود. تنها بخش‌های انتخاب‌شده تغییر می‌کنند.
- پیش از جایگزینی، برنامه تلاش می‌کند یک فایل پشتیبان جداگانه از وضعیت فعلی بخش‌های انتخاب‌شده با نامی متمایز دانلود کند. اگر تولید آن ممکن نباشد، دلیل و نبود نسخهٔ بازگشت پایدار پیش از ادامه اعلام می‌شود. هنگام نوشتن چند کلید، برنامه مقدار قبلی را در حافظه نگه می‌دارد، مقدار نوشته‌شده را بازخوانی و تأیید می‌کند و در خطا برای بازگردانی وضعیت قبلی تلاش می‌کند. پس از بارگذاری مجدد، کلیدهای ذخیره‌شده و داده‌های زندهٔ تنظیمات، پروژه و کتابخانه‌ها دوباره بررسی می‌شوند؛ اگر این بررسی کامل نباشد، هشدار نمایش داده می‌شود. برای جلوگیری از مهاجرت قدیمی، هنگام بازیابی پروژه، ارتقای خودکار الگوی قدیمیِ صفحهٔ آغازین در همان بارگذاری غیرفعال می‌شود. localStorage تراکنش اتمیک واقعی ارائه نمی‌کند؛ ذخیره‌شدن فایل دانلودی نیز باید توسط کاربر بررسی شود و بازگشت پس از بسته‌شدن تب، خرابی مرورگر یا شکست هم‌زمان ذخیره و بازگردانی تضمین نمی‌شود.
- ادغام فقط برای کتابخانه‌های سفارشی، بانک‌های کلمات و فهرست درج سریع ارائه می‌شود. آیتم‌های تکراری با شناسهٔ پایدار و در درج سریع همچنین با عنوان تشخیص داده می‌شوند؛ در تعارض، دادهٔ فعلی اولویت دارد. ادغام تنظیمات و فایل‌های پروژه برای این مدل داده معنادار نیست و ارائه نمی‌شود.
- اندازهٔ فایل ورودی و خروجی حداکثر ۵ مگابایت است. برای جلوگیری از تداخل با ویرایش‌های ذخیره‌نشده، پیش از پشتیبان‌گیری یا بازیابی بانک کلمات و فهرست درج سریع، تغییرات باز باید ذخیره یا لغو شوند.
- فایل پشتیبان رمزگذاری نمی‌شود و ممکن است شامل کد پروژه، کتابخانه‌ها و داده‌های سفارشی باشد؛ آن را امن نگهداری کنید. فایل در محل دانلود انتخابی کاربر ذخیره می‌شود و به‌خودی‌خود همگام‌سازی میان دستگاه‌ها ایجاد نمی‌کند.
- منطق قالب و بازگردانی خطای ذخیره‌سازی را می‌توان با دستورهای node --check backup-restore.js و node scripts/check-backup-restore.mjs بررسی کرد. آزمون‌های خودکار جایگزین آزمون دستی رابط، دانلود و بازیابی در مرورگر نیستند.
- پشتیبان‌گیری و بازیابی به ساخت خروجی مستقل وابسته نیستند؛ فایل `index-test-etitor.html` خارج از روند عادی بررسی‌ها باقی می‌ماند و فقط با دستور صریح کاربر ساخته یا بازسازی می‌شود.
