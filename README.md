# ویرایشگر HTML، CSS و JavaScript

این مخزن شامل دو ابزار تحت وب برای ساخت و آزمایش رابط‌های وب است:

1. **ویرایشگر کد (Editor):** محیطی برای نوشتن HTML، CSS و JavaScript، مدیریت فایل‌های پروژه و مشاهدهٔ پیش‌نمایش زنده.
2. **ویرایشگر بصری (Visual Editor):** محیطی برای افزودن و جابه‌جایی اجزا، تنظیم ویژگی‌های هر المان و تولید کد؛ این محیط در فایل یکپارچهٔ `editor v.html` کنار ویرایشگر اصلی ارائه می‌شود.

هر دو ابزار با فناوری‌های استاندارد مرورگر و بدون نیاز به نصب وابستگی‌های npm اجرا می‌شوند.

## شروع سریع

### پیش‌نیازها

- یک مرورگر به‌روز مانند Chrome، Edge یا Firefox
- یک وب‌سرور محلی یا میزبانی استاتیک برای اجرای پوشهٔ پروژه
- **Node.js** فقط برای اجرای آزمون‌ها و بازسازی نسخهٔ مستقل؛ برای استفادهٔ معمول از برنامه لازم نیست.

### اجرا روی رایانهٔ شخصی

مخزن را دریافت کنید:

~~~bash
git clone https://github.com/alfamaniya/Editor-html-css-js.git
cd Editor-html-css-js
~~~

در مسیر اصلی پروژه یک وب‌سرور ساده اجرا کنید:

~~~bash
python -m http.server 8000
~~~

سپس نشانی‌های زیر را در مرورگر باز کنید:

| ابزار | نشانی محلی | فایل ورودی |
|---|---|---|
| ویرایشگر کد | http://localhost:8000/ | index.html |
| ویرایشگر بصری | از نوار بالای `editor v.html` گزینهٔ «ویرایشگر بصری» را انتخاب کنید | `editor v.html` |
| نسخهٔ مستقل ویرایشگر یکپارچه | http://localhost:8000/editor%20v.html | editor v.html |

می‌توانید از هر وب‌سرور استاتیکی دیگری نیز استفاده کنید. اجرای پروژه از طریق HTTP محلی معمولاً از محدودیت‌های دسترسی فایل در مرورگر جلوگیری می‌کند.

## ۱. ویرایشگر کد (Editor)

صفحهٔ اصلی پروژه در فایل index.html قرار دارد و منطق اصلی ویرایشگر در script.js پیاده‌سازی شده است.

### امکانات ویرایش کد

- سه محیط مجزا برای HTML، CSS و JavaScript
- برجسته‌سازی نحوی کد با لایهٔ نمایش متن و ویرایشگر متنی
- پیشنهادهای خودکار متناسب با زبان و زمینهٔ تایپ، از جمله تگ‌ها و ویژگی‌های HTML، ویژگی‌ها و مقادیر CSS و واژه‌ها و اعضای شناخته‌شدهٔ JavaScript
- پیشنهاد واژهٔ بعدی بر اساس الگوهای تعریف‌شده در بانک پیشنهادها
- نوار درج سریع برای افزودن قطعه‌کدهای آماده
- امکان مدیریت و سفارشی‌سازی دسته‌ها و بانک‌های پیشنهاد و آیتم‌های درج سریع
- جست‌وجو در کد و حرکت میان نتیجه‌ها
- بازگشت و انجام دوبارهٔ تغییرات، تورفتگی و ویرایش متن
- تشخیص برخی الگوهای HTML/CSS/JavaScript هنگام چسباندن کد در ویرایشگر HTML و انتقال دارایی‌های قابل تشخیص به فایل‌های مربوط
- انتخاب‌گر رنگ در زمینه‌های پشتیبانی‌شدهٔ CSS، ویژگی‌های رنگی HTML و کد JavaScript

پیشنهادهای خودکار و پردازش کد چسبانده‌شده بر اساس قواعد و الگوهای پیاده‌سازی‌شده عمل می‌کنند؛ بنابراین نباید آن‌ها را تجزیه‌گر کامل همهٔ حالت‌های استاندارد زبان‌ها در نظر گرفت.

### مدیریت پروژه و فایل‌ها

- ساخت، بازنام‌گذاری، حذف و انتخاب فایل
- پشتیبانی از چند فایل HTML، CSS و JavaScript در یک پروژه
- جست‌وجو، فیلتر و مرتب‌سازی فهرست فایل‌ها
- نگهداری فایل فعال و آخرین فایل انتخاب‌شده در هر زبان
- نمایش وضعیت تغییرات ذخیره‌نشده
- ذخیرهٔ خودکار تغییرات پروژه در حافظهٔ محلی مرورگر و امکان ذخیرهٔ دستی

ساختار پروژهٔ ویرایشگر به یک مجموعهٔ ثابت سه‌فایلی محدود نیست؛ فایل‌های هم‌نوع متعدد می‌توانند در پروژه نگهداری شوند.

### پیش‌نمایش زنده

خروجی در یک iframe با محتوای تولیدشده از فایل‌های پروژه نمایش داده می‌شود. به‌روزرسانی خودکار پیش‌نمایش قابل فعال یا غیرفعال‌کردن است و فاصلهٔ زمانی آن از تنظیمات برنامه قابل تغییر است.

کد JavaScript پروژه در محیط پیش‌نمایش اجرا می‌شود. ویژگی sandbox برای iframe تنظیم شده است، اما این موضوع جایگزین بررسی و اعتماد به کدی که خودتان وارد می‌کنید نیست. کد ناشناس یا غیرقابل اعتماد را اجرا نکنید.

### کتابخانه‌ها

پنل کتابخانه‌ها برای جست‌وجو و انتخاب کتابخانه‌های CSS و JavaScript، افزودن کد سفارشی، فعال یا غیرفعال‌کردن کتابخانه‌های ذخیره‌شده و استفاده از نسخه‌های میزبانی‌شده در CDN در نظر گرفته شده است.

- دریافت فایل کتابخانه از CDN به اتصال اینترنت نیاز دارد.
- همهٔ کتابخانه‌ها صرفاً با بارگذاری یک فایل آمادهٔ اجرا نیستند؛ برخی به وابستگی، فایل جانبی یا راه‌اندازی اختصاصی نیاز دارند.
- فقط کد و نسخه‌های منابع قابل اعتماد را به پروژه اضافه کنید.

### تنظیمات و ابزارهای کمکی

- تنظیم ظاهر، رنگ تأکیدی و تراکم رابط
- تنظیم اندازهٔ قلم و نسبت فضای ویرایشگر به پیش‌نمایش
- کنترل پیشنهاد خودکار و رفتار به‌روزرسانی پیش‌نمایش
- درخت واژه‌ها برای مرور و جست‌وجوی عناصر، ویژگی‌ها، اعضا و نمونه‌کدهای موجود در داده‌های برنامه
- راهنمای داخلی برنامه به زبان‌های فارسی و انگلیسی
- مدیریت بانک پیشنهادها و فهرست درج سریع از بخش تنظیمات

### خروجی گرفتن از پروژه

ویرایشگر دو روش اصلی برای دریافت خروجی دارد:

**خروجی HTML تکی:** فایل HTML نهایی را با کدهای قابل تجمیع درون خودش تولید و دانلود می‌کند.

**خروجی چندفایلی:** چهار فایل جداگانه ایجاد می‌کند:

- فایل HTML
- فایل CSS
- فایل JavaScript
- فایل متنی فهرست کتابخانه‌ها با پسوند libs.txt

در زمان خروجی گرفتن، ارجاع‌های محلی و وابستگی‌هایی که امکان تجمیع ایمن آن‌ها وجود ندارد ممکن است حفظ شوند و برنامه دربارهٔ آن‌ها هشدار می‌دهد. پس از دانلود، مسیر فایل‌های وابسته را نیز بررسی کنید.

### پشتیبان‌گیری و بازیابی

از بخش تنظیمات می‌توان از داده‌های پشتیبانی‌شده نسخهٔ JSON تهیه کرد و بعداً آن را بازیابی کرد. بخش‌های قابل انتخاب عبارت‌اند از:

- تنظیمات و وضعیت‌های مرتبط با محیط کار
- پروژه و فایل‌های آن
- کتابخانه‌های سفارشی
- بانک‌ها، دسته‌بندی‌ها و واژه‌های پیشنهادی ذخیره‌شده
- فهرست درج سریع و تغییرات آیتم‌های پیش‌فرض

فایل پشتیبان دارای شناسهٔ قالب و شمارهٔ نسخه است و پیش از بازیابی اعتبارسنجی می‌شود. امکان جایگزینی بخش‌های انتخاب‌شده وجود دارد؛ حالت ادغام فقط برای کتابخانه‌ها، واژه‌های پیشنهادی و فهرست درج سریع پشتیبانی می‌شود. در تعارض شناسه یا عنوان، قواعد ادغام برنامه داده‌های فعلی را در اولویت قرار می‌دهند.

## ۲. ویرایشگر بصری (Visual Editor)

منبع این محیط در پوشهٔ `src/features/visual-editor/` نگهداری می‌شود. فایل نهایی `editor v.html` نسخهٔ کامل این محیط را همراه با ویرایشگر اصلی در یک HTML مستقل بسته‌بندی می‌کند. برای استفاده از هر دو محیط، فایل `editor v.html` را باز کنید و از نوار بالایی میان آن‌ها جابه‌جا شوید.

### محیط طراحی

- کتابخانهٔ اجزای آماده با دسته‌بندی چیدمان، محتوا، فرم و رسانه
- جست‌وجو و فیلتر اجزا و تغییر شیوهٔ نمایش فهرست
- افزودن اجزا با کشیدن آن‌ها به بوم طراحی
- افزودن HTML سفارشی
- انتخاب هر جزء روی بوم و بازکردن پنل تنظیمات همان جزء
- تغییر اندازه و جابه‌جایی مرز میان ویرایشگر کد و فضای طراحی

### اجزای آماده

کتابخانهٔ اولیه شامل ۲۱ نوع جزء است:

| گروه | اجزا |
|---|---|
| فرم و ورودی | Button، Input، Textarea، Checkbox، Select، Form |
| محتوا | Text، Heading، Paragraph، Badge، Link، Card |
| چیدمان | Box، Container، Section، Divider، Spacer |
| رسانه | Image، Video، Avatar |
| سفارشی | Custom HTML |

### تنظیم ظاهر و رفتار

با انتخاب جزء، پنل تنظیمات آن نمایش داده می‌شود. گزینه‌های قابل تنظیم، بسته به نوع جزء، شامل موارد زیر هستند:

- رنگ پس‌زمینه و متن، اندازه، ابعاد و گوشه‌ها
- سایه، حاشیه، فاصله‌گذاری و موقعیت
- ویژگی‌های متنی و نحوهٔ نمایش
- افکت‌های هنگام قرارگرفتن نشانگر روی جزء
- تعریف تعامل‌ها و رویدادهایی مانند کلیک، تغییر مقدار، تمرکز و ارسال فرم

انواع تعامل آماده شامل نمایش پیام، ثبت در کنسول، تغییر متن یا پس‌زمینه، تغییر کلاس، پنهان‌سازی یا نمایش جزء، هدایت به نشانی، تمرکز، پیمایش به عنصر و کپی متن است.

### تولید و ویرایش کد

طراح بصری سه خروجی HTML، CSS و JavaScript تولید می‌کند. کد هر زبان در تب جداگانه نمایش داده می‌شود و امکان ویرایش دستی و کپی کد وجود دارد.

دکمهٔ **Sync from Design** کد زبان انتخاب‌شده را با وضعیت فعلی طراحی همگام می‌کند؛ در نتیجه ممکن است ویرایش دستی همان زبان جایگزین شود. پیش از همگام‌سازی، کد موردنیاز را کپی یا ذخیره کنید.

وضعیت اجزا، انتخاب فعلی، تب فعال و بافرهای کد در حافظهٔ محلی مرورگر نگهداری می‌شوند.

## ۳. ذخیره‌سازی و حریم داده‌ها

هر دو ابزار از localStorage مرورگر برای نگهداری داده‌های خود استفاده می‌کنند؛ کلیدهای ذخیره‌سازی دو ابزار از هم جدا هستند.

- داده‌ها به نمایهٔ همان مرورگر وابسته‌اند و به‌صورت خودکار میان دستگاه‌ها یا مرورگرهای مختلف همگام نمی‌شوند.
- پاک‌کردن داده‌های سایت، استفاده از حالت خصوصی یا تغییر نمایهٔ مرورگر ممکن است دسترسی به پروژه‌ها و تنظیمات ذخیره‌شده را از بین ببرد.
- ذخیره‌سازی محلی جایگزین کنترل نسخه یا نسخهٔ پشتیبان مستقل نیست.
- از پروژه‌های مهم مرتباً خروجی یا نسخهٔ پشتیبان تهیه کنید.

## ۵. ساخت نسخهٔ مستقل ویرایشگر

فایل نهایی `editor v.html` از دو سند کامل Editor اصلی و Visual Editor ساخته می‌شود. منابع CSS و JavaScript هر دو محیط داخل فایل جاسازی می‌شوند و هر محیط در iframe و سند `srcdoc` جداگانه اجرا می‌شود تا شناسه‌ها، استایل‌ها و رویدادهای رابط با یکدیگر تداخل نداشته باشند. نوار بالایی امکان جابه‌جایی میان دو محیط را فراهم می‌کند. فایل خروجی برای اجرای خود به فایل جانبی محلی وابسته نیست.

از مسیر اصلی مخزن فرمان‌های زیر را اجرا کنید:

~~~bash
node scripts/build-test-editor.mjs
node scripts/check-standalone-editor.mjs
node scripts/build-standalone-visual-editor.mjs
node scripts/check-standalone-visual-editor.mjs
node scripts/build-combined-editor.mjs
node scripts/check-combined-editor.mjs
~~~

اسکریپت ساخت، منابع مورد انتظار را با ترتیب مشخص از HTML اصلی استخراج و در فایل مستقل جاسازی می‌کند. سپس وجود منابع، نبود ارجاع‌های محلی باقی‌مانده، یکتایی منابع جاسازی‌شده و تطابق محتوای جاسازی‌شده با فایل‌های اصلی را بررسی می‌کند.

اعتبارسنج مستقل نیز ساختار HTML، تعادل جداکننده‌های CSS، نحو JavaScript و حضور کنترل‌های اصلی را بررسی می‌کند.

دو خروجی index-test-etitor.html و standalone-visual-editor.html فقط فایل‌های واسط موقت برای ساخت و اعتبارسنجی هستند و در مخزن نگهداری نمی‌شوند. فایل قابل استفاده و تحویل، editor v.html است.

فایل tools/build-single-file.js صرفاً یک ورودی سازگاری برای اجرای سازندهٔ اصلی است؛ مسیر توصیه‌شده همان scripts/build-test-editor.mjs است.

## ۶. آزمون و کنترل کیفیت

برای اجرای آزمون‌های مخزن، Node.js نصب باشد. برای سازگاری با گردش‌کارهای ساخت و ارسال GitHub Actions، استفاده از Node.js 24 توصیه می‌شود؛ گردش‌کارهای بررسی اصلی از Node.js 20 نیز استفاده می‌کنند.

فرمان‌ها را از ریشهٔ مخزن اجرا کنید:

## ۷. گردش‌کارهای GitHub Actions

چهار گردش‌کار در پوشهٔ .github/workflows تعریف شده‌اند:

### ساخت و همگام‌سازی نسخهٔ مستقل

فایل build-test-editor.yml پس از تغییر منابع مؤثر بر خروجی در شاخهٔ main به‌صورت خودکار اجرا می‌شود. این گردش‌کار:

1. نحو فایل‌های JavaScript و اسکریپت‌های آزمون را بررسی می‌کند.
2. آزمون‌های یکپارچگی، پردازش کد، رنگ، صفحه‌کلید، هم‌ترازی و بازیابی را اجرا می‌کند.
3. نسخه‌های واسط Editor و Visual Editor را از منابع اصلی می‌سازد.
4. دو محیط را در فایل نهایی editor v.html بسته‌بندی و اعتبارسنجی می‌کند.
5. با Chromium اجرای هر دو iframe، پنجرهٔ تنظیمات Editor، پنل ویژگی‌های Visual Editor و ذخیره‌سازی مرورگر را آزمایش می‌کند.
6. فایل نهایی را در main ثبت می‌کند و خروجی‌های واسط را از مخزن حذف می‌کند.

اجرای دستی همین گردش‌کار از زبانهٔ Actions امکان‌پذیر است، اما ورودی تأیید ساخت باید فعال شود.

### بررسی فایل اصلی

- check-index.yml وجود و ساختار فایل اصلی، منابع محلی، پردازش کد چسبانده‌شده، رفتار صفحه‌کلید تنظیمات، پشتیبان‌گیری و نحو فایل‌های JavaScript مرتبط را بررسی می‌کند.
- check-index-integrity.yml کنترل مستقل‌تری برای یکپارچگی ساختار و جداکننده‌های index.html اجرا می‌کند.

این گردش‌کارها بر اساس شاخه و مسیر فایل‌های تغییرکرده در push یا pull request اجرا می‌شوند.

### ارسال فایل یکپارچه به ایمیل شرکت

گردش‌کار company-delivery.yml فقط با اجرای دستی و فعال‌کردن ورودی confirm_send قابل اجراست. این Workflow فایل ثبت‌شدهٔ editor v.html را می‌خواند، آن را بدون بازتولید اعتبارسنجی می‌کند و متن کامل HTML را در بدنهٔ یک ایمیل قرار می‌دهد. فایل به‌صورت پیوست ارسال نمی‌شود و نسخهٔ موجود در مخزن تغییر نمی‌کند.

### پیکربندی ایمیل

در مسیر **Settings → Secrets and variables → Actions** مخزن، Secretهای زیر را تعریف کنید:

| نام Secret | توضیح |
|---|---|
| SMTP_SERVER | نشانی سرور SMTP |
| SMTP_PORT | شمارهٔ درگاه SMTP |
| SMTP_USERNAME | نام کاربری یا نشانی حساب فرستنده |
| SMTP_PASSWORD | رمز عبور یا رمز اختصاصی برنامه برای SMTP |
| COMPANY_EMAIL | نشانی دریافت‌کنندهٔ ایمیل در شرکت |
| SMTP_SECURE | اختیاری؛ مقدار true یا false مطابق شیوهٔ اتصال SMTP |

مقادیر SMTP را از ارائه‌دهندهٔ سرویس ایمیل دریافت کنید. در صورت فعال‌بودن احراز هویت دومرحله‌ای ممکن است رمز اختصاصی برنامه لازم باشد. هیچ‌یک از این مقادیر را در کد یا فایل‌های عمومی مخزن قرار ندهید.

### اجرای ارسال

1. مخزن را در GitHub باز کنید و وارد **Actions** شوید.
2. گردش‌کار **ارسال کد کامل editor v.html به ایمیل شرکت** را انتخاب کنید.
3. روی **Run workflow** کلیک کنید و شاخهٔ موردنظر را انتخاب کنید.
4. ورودی تأیید ارسال را فعال کنید.
5. پس از پایان اجرا، وضعیت Job ارسال و نتیجهٔ اعتبارسنجی فایل را بررسی کنید.

اگر تأیید صریح فعال نشده باشد، فرایند ارسال انجام نمی‌شود. اگر اعتبارسنجی فایل‌ها یا تنظیمات SMTP ناموفق باشد، وضعیت خطا در اجرای گردش‌کار نمایش داده می‌شود.

## ۸. نکات نگهداری و توسعه
