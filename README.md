# ویرایشگر HTML / CSS / JavaScript

یک ویرایشگر کد تحت وب برای نوشتن و آزمایش HTML و CSS و JavaScript در یک محیط واحد. پروژه با فناوری‌های استاندارد وب ساخته شده و برای اجرای نسخهٔ اصلی به مرحلهٔ build یا نصب وابستگی‌های npm نیاز ندارد؛ کافی است فایل‌های پروژه را با هم نگه دارید و `index.html` را در مرورگر باز کنید.

مخزن: [alfamaniya/Editor-html-css-js](https://github.com/alfamaniya/Editor-html-css-js)

## امکانات اصلی

- ویرایش HTML، CSS و JavaScript در یک رابط واحد.
- پیش‌نمایش زندهٔ نتیجه در iframe؛ تغییرات پس از مکث کوتاه در ویرایش به پیش‌نمایش فرستاده می‌شوند.
- پیشنهادهای خودکار کد (IntelliSense) برای بخش‌هایی از HTML، CSS و JavaScript.
- راهنمای درون‌خطی فارسی برای نوع مقدار مورد انتظار بعضی ویژگی‌های CSS، در همان پنجرهٔ پیشنهادها؛ برای مثال مقدارهای فاصله و اندازه، رنگ و زمان.
- بانک دادهٔ محلی برای پیشنهادها و توضیحات آموزشی؛ این بانک به‌صورت خودکار از منابع آنلاین به‌روزرسانی نمی‌شود.
- مدیریت چند فایل در پروژه، شامل ساخت فایل، جست‌وجو و فیلتر بر اساس نوع و مرتب‌سازی.
- جست‌وجو در کد و حرکت میان نتایج.
- Undo و Redo، تغییر اندازهٔ قلم، پاک‌کردن فایل فعلی یا همهٔ فایل‌ها، بازنشانی کد نمونه و ذخیره در مرورگر.
- دانلود خروجی HTML با نام دلخواه.
- بخش کتابخانه‌ها برای افزودن کد CSS یا JavaScript و انتخاب از فهرست کتابخانه‌های آماده.
- پنل راهنما با محتوای انگلیسی و فارسی.

## شروع به کار

### اجرای محلی

1. مخزن را دریافت یا Clone کنید.
2. فایل‌های پروژه را در ساختار اصلی خود نگه دارید؛ فایل‌های JavaScript داده‌ای باید در کنار `index.html` باشند.
3. فایل `index.html` را در یک مرورگر به‌روز باز کنید.
4. کد را در ویرایشگرها تغییر دهید و نتیجه را در پنل پیش‌نمایش بررسی کنید.

برای دریافت مخزن با Git:

```bash
git clone https://github.com/alfamaniya/Editor-html-css-js.git
cd Editor-html-css-js
```

سپس `index.html` را باز کنید. اگر مرورگر یا تنظیمات محیط محلی محدودیت‌هایی برای بارگذاری منابع ایجاد کرد، پروژه را با یک وب‌سرور محلی ساده اجرا کنید.

### وابستگی‌ها

نسخهٔ اصلی پروژه از HTML، CSS و JavaScript سمت مرورگر استفاده می‌کند و در فایل‌های اصلی به فرایند build مبتنی بر npm وابسته نیست. برخی کتابخانه‌های انتخابی از CDN بارگیری می‌شوند و بنابراین استفاده از آن‌ها ممکن است به اتصال اینترنت نیاز داشته باشد.

## ساختار فایل‌ها

| فایل | مسئولیت |
|---|---|
| `index.html` | ساختار رابط، کنترل‌های ویرایشگر، پنل فایل‌ها، پنل کتابخانه‌ها، راهنما و iframe پیش‌نمایش |
| `style.css` | ظاهر رابط، چیدمان، پنجره‌های پیشنهاد، پنل‌ها و قواعد واکنش‌گرایی |
| `script.js` | منطق اصلی ویرایشگر، مدیریت فایل‌ها و وضعیت، جست‌وجو، پیشنهادها، ذخیره‌سازی، کتابخانه‌ها و ساخت خروجی |
| `intellisense-data.js` | داده‌های پیشنهاد خودکار برای HTML، CSS و JavaScript |
| `css-learning-data.js` | داده‌های توضیحی و آموزشی برای عناصر و ویژگی‌های رایج HTML و ویژگی‌ها و مقادیر CSS |

نام یا مسئولیت دقیق بخش‌های داخلی ممکن است با توسعهٔ پروژه تغییر کند؛ برای جزئیات اجرایی، خود فایل‌ها مرجع نهایی هستند.

## روش استفاده

1. کد HTML را در بخش HTML، سبک‌ها را در CSS و رفتار تعاملی را در JavaScript بنویسید.
2. پیش‌نمایش را بررسی کنید. خطاهای JavaScript در صورت دریافت پیام خطا از iframe می‌توانند به‌شکل اعلان در رابط نشان داده شوند.
3. از جست‌وجو برای پیدا کردن متن در کد استفاده کنید و با دکمه‌های قبلی/بعدی میان نتایج حرکت کنید.
4. از Undo و Redo برای برگشت یا تکرار تغییرات استفاده کنید.
5. برای نگه‌داشتن کار در همان مرورگر از Save و برای گرفتن فایل خروجی از Download استفاده کنید.
6. در صورت نیاز از File Manager برای ساخت فایل‌های HTML، CSS یا JavaScript و مرتب‌سازی فهرست فایل‌ها کمک بگیرید.

**توجه:** ذخیره در مرورگر با ذخیره در GitHub یا فضای ابری یکسان نیست. داده‌های محلی به همان مرورگر و همان مبدأ وابسته‌اند و با پاک‌کردن داده‌های سایت ممکن است از دست بروند.

## مدیریت فایل‌های پروژه

پنل Files برای کار با چند فایل در پروژه در نظر گرفته شده است. امکانات قابل مشاهده شامل ساخت فایل جدید، جست‌وجوی نام فایل، فیلتر بر اساس HTML/CSS/JavaScript و مرتب‌سازی بر اساس ترتیب افزودن، نوع یا نام است.

- نام فایل باید یکتا باشد و حداکثر ۱۲۰ نویسه داشته باشد.
- دکمهٔ Clear محتوای فایل جاری را پاک می‌کند؛ Clear All برای پاک‌کردن همهٔ فایل‌هاست.
- Reset کد نمونهٔ پیش‌فرض را برمی‌گرداند؛ پیش از استفاده، تغییرات مهم را ذخیره یا دانلود کنید.
- قابلیت پیست‌کردن یک سند کامل HTML، در صورت شناسایی سند، برای تبدیل آن به ساختار داخلی ویرایشگر طراحی شده است. این مسیر جایگزین یک فرایند عمومی و کامل واردکردن همهٔ قالب‌های فایل نیست.

## IntelliSense و راهنمای کد

پنجرهٔ پیشنهادها بر اساس زمینهٔ فعلی تایپ، گزینه‌های مرتبط را نمایش می‌دهد. داده‌های پیشنهادی در فایل `intellisense-data.js` نگهداری می‌شوند و توضیحات آموزشی در `css-learning-data.js` قرار دارند.

برای راهنمای مقدار CSS، پس از نوشتن ویژگی و دونقطه، مانند `padding:` یا `color:`، راهنمای کوتاهی ممکن است در بالای فهرست پیشنهادها نمایش داده شود. این راهنما یک توضیح کمکی است، نه اعتبارسنج کامل استاندارد CSS؛ پوشش آن برای همهٔ ویژگی‌ها و همهٔ حالت‌های نحوی کامل نیست. گزینه‌های واقعی پیشنهاد همچنان جداگانه انتخاب می‌شوند.

## کتابخانه‌های جانبی

پنل Libraries دو روش کلی دارد:

- انتخاب یک مورد از کاتالوگ کتابخانه‌های آماده؛
- افزودن دستی کتابخانه با نام، نوع CSS یا JS و چسباندن کد آن.

انتخاب یک مورد از کاتالوگ به‌تنهایی به معنی فعال‌شدن خودکار آن در پروژه نیست. طبق رابط برنامه، باید کد کتابخانه به Saved Libraries افزوده و در صورت نیاز فعال شود. برخی کتابخانه‌ها وابستگی‌های جانبی یا تنظیمات خاص دارند؛ مستندات رسمی همان کتابخانه را بررسی کنید.

بارگیری از CDN به اتصال اینترنت و در دسترس بودن میزبان وابسته است. اگر بارگیری خودکار مسدود شد، می‌توانید از منبع رسمی کتابخانه فایل مناسب را بگیرید و کد را دستی وارد کنید. نسخه‌ها و نشانی‌های کاتالوگ ممکن است در گذر زمان تغییر کنند.

## پیش‌نمایش و خروجی

ویرایشگر از محتوای HTML، CSS و JavaScript پروژه برای ساخت سند HTML پیش‌نمایش استفاده می‌کند. در خروجی، کدهای پروژه و کتابخانه‌های فعال می‌توانند در سند جاسازی شوند؛ ارجاع‌های محلی‌ای که محتوایشان در پروژه موجود و جاسازی‌شدنی است برای جلوگیری از بارگذاری تکراری مدیریت می‌شوند. ارجاع‌های راه‌دور و فایل‌های محلیِ جاسازی‌نشده ممکن است همچنان به فایل بیرونی نیاز داشته باشند.

- **Preview** برای مشاهدهٔ نتیجه در محیط داخلی است.
- **Download** برای دریافت سند HTML تولیدشده است.
- اگر خروجی به فایل‌ها یا سرویس‌های بیرونی وابسته باشد، یک فایل HTML به‌تنهایی الزاماً تمام وابستگی‌ها را همراه خود ندارد.
- کد JavaScript نوشته‌شده توسط کاربر در iframe اجرا می‌شود. Sandbox مرورگر بخشی از دسترسی‌های iframe را محدود می‌کند، اما نباید اجرای کد ناشناس را بی‌خطر فرض کرد.

## ذخیره‌سازی و حریم خصوصی

این پروژه عمدتاً در مرورگر اجرا می‌شود و برای ذخیرهٔ کار از قابلیت ذخیره‌سازی محلی مرورگر استفاده می‌کند. این رفتار به معنی همگام‌سازی ابری نیست. اگر از کتابخانه‌های CDN استفاده کنید، مرورگر برای دریافت آن‌ها به سرویس‌های میزبان درخواست شبکه می‌فرستد.

کدهای ناشناس را با احتیاط اجرا کنید، به‌ویژه اگر شامل اسکریپت‌های بیرونی یا دسترسی به شبکه باشند. پیش از پاک‌کردن داده‌های مرورگر یا استفاده از Reset/Clear All، از پروژهٔ مهم خروجی بگیرید.

## محدودیت‌ها

- پروژه یک ویرایشگر سبک سمت مرورگر است؛ جایگزین کامل IDEهای حرفه‌ای یا ابزارهای build نیست.
- راهنمای آموزشی و پیشنهادها پوشش کامل تمام استانداردهای HTML، CSS و JavaScript را تضمین نمی‌کنند.
- داده‌های راهنما آفلاین و ایستا هستند و خودکار از MDN یا استانداردها همگام نمی‌شوند.
- کتابخانه‌های CDN ممکن است در حالت آفلاین یا شبکه‌های محدود کار نکنند.
- خروجی مستقل تنها زمانی کاملاً مستقل است که تمام منابع لازم واقعاً در آن جاسازی شده باشند.
- آزمون دستی در مرورگرهای مختلف، بررسی Console و آزمایش سناریوهای پیچیده همچنان برای انتشارهای مهم توصیه می‌شود.

## آزمودن و عیب‌یابی

پس از هر تغییر مهم، این موارد را بررسی کنید:

- بازشدن `index.html` و نمایش همهٔ پنل‌ها؛
- ویرایش هر سه زبان و به‌روزرسانی پیش‌نمایش؛
- عملکرد پیشنهادها در HTML، CSS و JavaScript؛
- نمایش راهنمای مقدار برای ویژگی‌هایی مانند `padding:`، `color:`، `display:` و `transition-duration:`؛
- ذخیره، بارگذاری مجدد صفحه و بازیابی پروژه؛
- ساخت و مرتب‌سازی فایل‌ها؛
- فعال‌کردن یک کتابخانهٔ CSS و یک کتابخانهٔ JavaScript؛
- دانلود خروجی و بازکردن آن جدا از رابط ویرایشگر؛
- بررسی خطاهای Console و درخواست‌های ناموفق Network.

اگر مشکلی دیدید، مراحل بازتولید، مرورگر و پیام خطای Console را در یک Issue ثبت کنید.

## مشارکت در پروژه

برای پیشنهاد قابلیت یا گزارش اشکال:

1. ابتدا Issues موجود را بررسی کنید.
2. مسئله یا پیشنهاد را با مراحل بازتولید و نتیجهٔ مورد انتظار توضیح دهید.
3. برای تغییرات کد، یک شاخهٔ جدا ایجاد کنید و تغییرات را در Pull Request ارائه دهید.
4. در توضیح Pull Request مشخص کنید چه چیزی تغییر کرده و چه آزمون‌هایی واقعاً اجرا شده‌اند.
