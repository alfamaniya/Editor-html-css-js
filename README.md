# ویرایشگر HTML / CSS / JavaScript

ویرایشگر تحت وب برای ساخت، ویرایش، پیش‌نمایش، مدیریت و خروجی‌گرفتن از پروژه‌های **HTML، CSS و JavaScript**. پروژه با فناوری‌های استاندارد مرورگر نوشته شده است و برای اجرای نسخهٔ اصلی به نصب پکیج یا فرایند Build نیاز ندارد.

## قابلیت‌ها

- ویرایش جداگانهٔ HTML، CSS و JavaScript با شمارهٔ خطوط و رنگ‌آمیزی نحوی.
- پیش‌نمایش زنده در یک `iframe` ایزوله‌شده.
- تکمیل خودکار تگ‌ها و ویژگی‌های HTML، ویژگی‌ها و مقادیر CSS، کلمات و اعضای JavaScript و نمونه‌کدها.
- پیشنهاد ادامهٔ کد بر اساس زمینهٔ فعلی نوشتن؛ این قابلیت مجموعه‌ای از قواعد و داده‌های ازپیش‌تعریف‌شده است، نه مدل هوش مصنوعی یا تحلیل‌گر کامل زبان.
- **Word Tree**؛ درخت زنده و قابل جست‌وجو از بانک‌های پیشنهاد کد با فیلتر زبان و توضیح فارسی همراه نمونه‌کد.
- مدیریت فایل‌های پروژه: ایجاد، بازنام‌گذاری، حذف و بازیابی، جست‌وجو و مرتب‌سازی.
- مدیریت کتابخانه‌های CSS و JavaScript؛ امکان افزودن کد سفارشی یا دریافت برخی کتابخانه‌ها از CDN.
- جست‌وجو در کد، Undo/Redo، تنظیم اندازهٔ قلم، ابزارهای تورفتگی و درج سریع نمادها.
- ذخیرهٔ پروژه در حافظهٔ محلی مرورگر، پیام خطا هنگام ناموفق بودن ذخیره و امکان دریافت نسخهٔ بازیابی در برخی خطاهای داده.
- خروجی به شکل یک فایل HTML مستقل یا بستهٔ چهارفایلی.
- نمایش زمان آخرین کامیت شاخهٔ `main` از GitHub، در صورت در دسترس بودن شبکه و API.

## درخت فایل‌های مخزن

```text
.
├── .github/
│   └── workflows/
│       ├── build-test-editor.yml
│       ├── check-index-integrity.yml
│       └── check-index.yml
├── scripts/
│   ├── build-test-editor.mjs
│   └── check-index-integrity.mjs
├── tools/
│   └── build-single-file.js
├── index.html
├── index-test-etitor.html
├── style.css
├── script.js
├── github-update.js
├── word-tree.js
├── html-suggestions.js
├── css-suggestions.js
├── js-suggestions.js
├── next-word-suggestions.js
├── tree-world-suggestion.md

```

> نام `index-test-etitor.html` عمداً مطابق مسیر فعلی مخزن نوشته شده است. گردش‌کار ساخت به همین نام وابسته است؛ آن را دستی تغییر نام ندهید، مگر آن‌که ارجاع‌های ساخت نیز اصلاح شوند. این فایل خروجی تولیدشده است؛ تغییرات اصلی را در فایل‌های منبع اعمال کنید.

## نقش فایل‌ها

| فایل یا پوشه | کاربرد |
|---|---|
| `index.html` | ساختار صفحه و رابط اصلی ویرایشگر و ارجاع به فایل‌های محلی |
| `style.css` | استایل عمومی، پنل‌ها، چیدمان و واکنش‌گرایی |
| `script.js` | منطق اصلی، مدیریت فایل‌ها، پیش‌نمایش، ذخیره‌سازی، تکمیل خودکار، کتابخانه‌ها و خروجی |
| `html-suggestions.js` | بانک پیشنهادهای HTML |
| `css-suggestions.js` | بانک پیشنهادهای CSS |
| `js-suggestions.js` | بانک پیشنهادهای JavaScript |
| `next-word-suggestions.js` | قواعد پیشنهاد ادامهٔ کد در زمینه‌های شناخته‌شده |
| `word-tree.js` | ساخت و نمایش درخت زنده از بانک‌های پیشنهاد |
| `github-update.js` | دریافت اطلاعات آخرین کامیت از GitHub |
| `tree-world-suggestion.md` | مستند متنی درخت قواعد پیشنهاد؛ در زمان اجرا بارگذاری نمی‌شود |
| `index-test-etitor.html` | نسخهٔ تک‌فایلی تولیدشده برای آزمایش و توزیع |
| `scripts/build-test-editor.mjs` | سازندهٔ اصلی نسخهٔ تک‌فایلی که GitHub Actions از آن استفاده می‌کند |
| `scripts/check-index-integrity.mjs` | بررسی ساختار تگ‌ها و جداکننده‌های کد در `index.html` |
| `tools/build-single-file.js` | سازندهٔ جایگزین؛ گردش‌کار اصلی مخزن از سازندهٔ فایل `.mjs` استفاده می‌کند |
| `.github/workflows/build-test-editor.yml` | بررسی نحو JavaScript و ساخت نسخهٔ تک‌فایلی |
| `.github/workflows/check-index-integrity.yml` | اجرای بررسی تگ‌ها، جداکننده‌ها و JavaScript درون‌خطی |
| `.github/workflows/check-index.yml` | بررسی ساختار `index.html`، ارجاع فایل‌های محلی و موارد پایهٔ اعتبارسنجی |

## اجرا در سیستم شخصی

برای اجرای نسخهٔ اصلی کافی است مخزن را دریافت کنید و فایل `index.html` را در مرورگر باز کنید. نصب وابستگی با npm لازم نیست. برای اجرای آزمون‌ها و ساخت نسخهٔ تک‌فایلی، **Node.js 20** را نصب داشته باشید؛ گردش‌کارهای GitHub نیز از Node.js 20 استفاده می‌کنند.

دستورهای زیر را از ریشهٔ مخزن اجرا کنید:

```bash
# بررسی ساختار HTML، تگ‌ها و جداکننده‌های کد
node scripts/check-index-integrity.mjs

# ساخت دوبارهٔ نسخهٔ تک‌فایلی
node scripts/build-test-editor.mjs
```

برای بررسی نحوی یک فایل JavaScript به‌تنهایی:

```bash
node --check script.js
```

پس از تغییر فایل‌های منبع، نسخهٔ تولیدشده را با `scripts/build-test-editor.mjs` بازسازی کنید. در مخزن، GitHub Actions نیز ساخت را هنگام Push به شاخهٔ `main` انجام می‌دهد.

## کنترل‌های خودکار GitHub Actions

- **Build standalone test editor:** نحو فایل‌های JavaScript منتخب را بررسی می‌کند و `index-test-etitor.html` را می‌سازد؛ در صورت تغییر خروجی، آن را Commit می‌کند.
- **Check index syntax and delimiters:** ساختار تگ‌های `index.html` و توازن جداکننده‌ها را بررسی می‌کند و نحو JavaScript درون‌خطی را با Node.js می‌سنجد.
- **Check index file:** ساختار پایهٔ HTML و وجود فایل‌های محلی ارجاع‌شده را بررسی می‌کند.

این کنترل‌ها برای یافتن گروهی از خطاهای رایج مفیدند، اما جایگزین اعتبارسنج کامل HTML/CSS، اجرای تعاملی در مرورگر یا آزمون سازگاری بین مرورگرها نیستند. وضعیت و گزارش هر اجرا در زبانهٔ **Actions** مخزن قابل مشاهده است.

## خروجی گرفتن

### فایل HTML مستقل

گزینهٔ فایل مستقل، HTML نهایی را به همراه CSS و JavaScript لازم در یک سند قرار می‌دهد تا برای اجرا به فایل‌های منبع محلی وابسته نباشد.

### بستهٔ چهارفایلی

بسته شامل چهار فایل با نام پایهٔ انتخاب‌شده است:

1. `نام.html` — سند HTML خروجی.
2. `نام.css` — کد CSS پروژه و کتابخانه‌های CSS فعال.
3. `نام.js` — کد JavaScript پروژه و کتابخانه‌های JavaScript فعال.
4. `نام.libs.txt` — نسخهٔ متنی کد کتابخانه‌های فعال.

این خروجی یک سامانهٔ Build چندصفحه‌ای نیست و ساختار کامل همهٔ فایل‌ها و دارایی‌های اصلی پروژه را در یک آرشیو بازسازی نمی‌کند. اگر پروژه به فایل‌های محلی دیگری وابسته است، خروجی را پیش از انتشار بررسی کنید.

## ذخیره‌سازی و حریم خصوصی

پروژه و تنظیمات محلی در حافظهٔ مرورگر نگه‌داری می‌شوند. پاک‌کردن داده‌های مرورگر می‌تواند نسخهٔ ذخیره‌شده را از بین ببرد؛ برای پروژه‌های مهم، مرتباً خروجی تهیه کنید. دسترسی به کتابخانه‌های CDN و نشانگر آخرین کامیت به اینترنت وابسته است.

## گزارش بررسی و اصلاح

- بررسی ارجاع‌های محلی در `index.html` نشان می‌دهد فایل‌های CSS و JavaScript موردنیاز در مخزن وجود دارند.
- بانک‌های پیشنهاد HTML، CSS و JavaScript به‌صورت فایل‌های جداگانه بارگذاری می‌شوند؛ نام آن‌ها با نام فایل‌های واقعی مستند شده است.
- ذخیره‌سازی ناموفق، دادهٔ پروژهٔ نامعتبر و شکست بعضی عملیات فایل باید به کاربر گزارش شود؛ مسیرهای بازیابی موجود برای کاهش خطر از دست‌رفتن داده طراحی شده‌اند.
- هنگام ساخت خروجی، برچسب‌های توضیحی تولیدشده از نام فایل یا کتابخانه پاک‌سازی می‌شوند تا نام‌هایی شامل پایان‌دهندهٔ کامنت یا شکست خط، کد خروجی را خراب نکنند.
- اصلاح اخیر: بررسی‌گر یکپارچگی، مکان‌نما را روی ابتدای تگ بسته‌شدن `</script>` نگه می‌داشت و همان تگ را بار دیگر می‌خواند؛ این رفتار خطاهای کاذب ایجاد می‌کرد. مکان‌نما اکنون پس از کل تگ بسته‌شدن قرار می‌گیرد. بعد از اصلاح، گردش‌کار بررسی تگ‌ها و گردش‌کار ساخت نسخهٔ مستقل با موفقیت اجرا شد.

## محدودیت‌های شناخته‌شده

- آزمون خودکار کامل مرورگر، آزمون انتها‌به‌انتها و بررسی چندمرورگری در مخزن پیکربندی نشده‌اند؛ تعاملات واقعی، دانلودها، فضای ذخیره‌سازی مرورگر و اندازهٔ صفحه باید دستی نیز بررسی شوند.
- تکمیل خودکار و پیشنهاد واژهٔ بعدی بر پایهٔ بانک‌های curated و قواعد سبک هستند و به‌اندازهٔ parser یا Language Server کامل نیستند.
- فایل درخت پیشنهادها مستندات متنی است؛ منبع قابلیت درخت زنده، بانک‌های پیشنهاد بارگذاری‌شده و `word-tree.js` هستند.
- در حال حاضر فایل مجوز `LICENSE` در ریشهٔ مخزن وجود ندارد. پیش از توزیع مجدد، شرایط مجوز را مشخص کنید.
