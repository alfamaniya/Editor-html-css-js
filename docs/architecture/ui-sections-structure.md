# ساختار رابط کاربری: وضعیت واقعی و مسیر توسعه

این سند جایگزین طرح قدیمی Futures است. پوشهٔ `futures/` در ساختار فعلی مخزن وجود ندارد و هیچ‌یک از مسیرهای آن نباید به‌عنوان ماژول اجرایی یا مقصد build معرفی شوند.

## اجزای فعال فعلی

| مسیر | مسئولیت |
|---|---|
| `index.html` | پوستهٔ اصلی، workspace، تب‌های HTML/CSS/JS، پنل‌ها و preview |
| `style.css` | استایل عمومی، لایهٔ ویرایشگر، layout و واکنش‌گرایی |
| `script.js` | منطق اصلی فایل‌ها، ویرایش، ذخیره، paste/import و preview |
| `src/features/workspace/file-manager/` | پنل و عملیات مدیریت فایل |
| `src/features/workspace/search/` | جست‌وجوی کد |
| `src/features/workspace/toolbar/` | سایدبار ابزارها |
| `src/features/settings/` | تنظیمات |
| `src/features/backup-restore/` | پشتیبان‌گیری و بازیابی |

## تصمیم موتور ویرایش

- صفحهٔ اصلی در حال حاضر از textarea استفاده می‌کند.
- CodeMirror در صفحه بارگذاری نمی‌شود و Monaco نیز موتور فعال پروژه نیست.
- pipeline قدیمی CodeMirror که به مسیر حذف‌شدهٔ `futures/editor/core/` خروجی می‌داد حذف شده است.
- تا زمانی که مهاجرت واقعی و تست‌شده به موتور دیگری انجام نشده، مستندات و رابط کاربری باید textarea را به‌عنوان موتور فعلی معرفی کنند؛ نباید قابلیت‌هایی مانند syntax diagnostics یا autocomplete حرفه‌ای موتور را ادعا کنند.

## مرزبندی قابلیت‌ها

1. ماژول‌های موجود در `src/features/` مرجع اجرایی هستند.
2. کد مشترک در `src/shared/` نگهداری می‌شود؛ نمونهٔ فعلی اعتبارسنجی مشترک نام فایل در `src/shared/validation/file-name.js` است.
3. قابلیت Visual Editor و انتخاب المان حذف شده است؛ preview زندهٔ معمولی حفظ شده است.
4. `index 2.html` یک نمونهٔ مستقل UI است و جزو build برنامهٔ اصلی نیست. کنترل‌های پیاده‌سازی‌نشده در آن غیرفعال هستند و navigation placeholder باید بدون مقصد جعلی نمایش داده شود.
5. هر قابلیت جدید باید همراه با markup، style، behavior و تست‌های قابل اجرا طراحی شود؛ وجود یک فایل یا پوشه به‌تنهایی به معنی فعال بودن قابلیت نیست.

## قواعد توسعه

- ابتدا API و مالکیت داده مشخص شود، سپس markup/CSS/JS جدا شوند.
- از ایجاد چند پیاده‌سازی فعال برای یک قابلیت خودداری شود.
- هر تغییر در شناسه‌های DOM باید تمام مصرف‌کنندگان آن را به‌روز کند.
- خروجی standalone فقط از فایل‌های فهرست‌شده در manifest ساخته شود.
- CI باید build و همهٔ checkهای مرتبط را اجرا کند.
- مستندات باید پس از تغییر ساختار با درخت واقعی Git همگام شوند.
