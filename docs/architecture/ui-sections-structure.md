# ساختار هفت بخش اصلی رابط کاربری

این سند قرارداد اولیهٔ پوشه‌بندی رابط کاربری آینده را ثبت می‌کند. هر هفت بخش جدید در پوشهٔ ریشهٔ `futures/` نگهداری می‌شوند تا با ماژول‌های قدیمی و فعال `src/features/` مخلوط نشوند. این پوشه فعلاً محل اسکلت‌بندی است و به رابط فعلی متصل نیست.

## هفت بخش اصلی

| پوشه | مسئولیت |
|---|---|
| `header/` | هدر سراسری با عرض کامل صفحه |
| `file-manager/` | پنل باز و بسته‌شوندهٔ سمت چپ برای مدیریت فایل‌ها |
| `editor/` | محیط اصلی ویرایش کد |
| `editor-terminal/` | پنل مستقل پایین محیط ویرایشگر؛ قابلیت‌های آن بعداً تعریف می‌شود |
| `right-menu/` | پنل باز و بسته‌شوندهٔ سمت راست؛ محتوای آن فعلاً تعیین نشده است |
| `live-preview/` | محیط نمایش زندهٔ خروجی |
| `preview-terminal/` | پنل مستقل پایین پیش‌نمایش؛ قابلیت‌های آن بعداً تعریف می‌شود |

## قرارداد سه‌فایلی

هر بخش اصلی و هر قابلیت فرزند که در آینده به آن اضافه شود، در حالت معمول سه فایل مستقل دارد. این ساختار فقط زیر `futures/` ساخته می‌شود و نباید پوشه‌های موجود `src/features/` را جابه‌جا یا جایگزین کند:

- `index.html`: قطعهٔ HTML همان بخش، نه یک سند کامل با تگ‌های `html`، `head` و `body`.
- `style.css`: استایل‌های اختصاصی همان بخش.
- `script.js`: منطق و رفتار همان بخش.

نمونه:

```text
futures/editor/
├── index.html
├── style.css
├── script.js
├── header/
│   ├── index.html
│   ├── style.css
│   └── script.js
└── search/
    ├── index.html
    ├── style.css
    └── script.js
```

## قواعد مهم

1. این فایل‌ها فعلاً اسکلت خالی هستند؛ ایجاد آن‌ها به معنی فعال یا متصل بودن بخش‌ها در رابط فعلی نیست.
2. کد واقعاً مشترک نباید در چند بخش کپی شود؛ جای آن در `src/shared/` است؛ کدهای مشترک فعلی همچنان در همان محل باقی می‌مانند.
3. چیدمان کلی، اتصال هفت بخش، مدیریت باز/بسته شدن پنل‌ها و هماهنگی اندازه‌ها باید در لایهٔ برنامه/پوسته مدیریت شود.
4. CSS هر بخش باید تا حد امکان محدوده‌دار باشد تا روی بخش‌های دیگر اثر ناخواسته نگذارد.
5. JavaScript هر بخش پس از تعیین روش بارگذاری و APIهای ارتباطی به برنامه متصل می‌شود؛ وجود فایل به معنی اجرای خودکار آن نیست.
6. فایل‌های فعلی مانند `src/features/live-preview/element-inspector.js` و ماژول‌های قدیمی `src/features/workspace/file-manager/` حفظ می‌شوند. انتقال یا ادغام آن‌ها مرحله‌ای جداگانه است.
7. فایل یکپارچهٔ `editor v.html` همچنان خروجی توزیع است و محل توسعهٔ مستقیم نیست.

## محل نگهداری و مرزبندی

- `futures/`: محل هفت بخش جدید رابط کاربری و قابلیت‌های فرزند آن‌ها.
- `src/features/`: محل ماژول‌ها و قابلیت‌های موجود پروژه؛ ساختار قدیمی آن دست‌نخورده باقی می‌ماند.
- فایل قدیمی `src/features/live-preview/element-inspector.js` عمداً در محل قبلی باقی مانده و با اسکلت جدید `futures/live-preview/` ادغام نشده است.

## هدر اختصاصی ویرایشگر

هدر داخلی بخش Editor در `futures/editor/header/` نگهداری می‌شود و سه فایل مستقل `index.html`، `style.css` و `script.js` دارد. این زیر‌بخش برای سازمان‌دهی نوار ابزار و تب‌های فایل است. در پوستهٔ نمایشی Futures، ظاهر این هدر شامل Undo، Redo، Clear و تب‌های پیش‌فرض HTML، CSS و JavaScript است. در این مرحله دکمه‌ها و تب‌ها صرفاً نمایشی هستند و رفتار ویرایش، بستن تب یا تأیید پاک‌سازی هنوز پیاده‌سازی نشده است.

این قانون، قرارداد بصری دائمی پروژه برای تمام توسعه‌های بعدی رابط کاربری است:

- تم اصلی رابط کاربری باید همیشه **مشکی و فیروزه‌ای (Black & Turquoise)** باشد.
- رنگ‌های پایه:
  - پس‌زمینه اصلی: `#080B0D`
  - هدر: `#0D1214`
  - پنل‌ها: `#111719`
  - پنل‌های برجسته: `#192326`
  - ترمینال: `#0B1012`
  - خطوط جداکننده: `#263438`
  - رنگ اصلی فیروزه‌ای: `#27C9BE`
  - فیروزه‌ای روشن برای تاکید و حالت فعال: `#55E5D9`
  - متن اصلی: `#E6F0F0`
  - متن فرعی: `#91A5A5`
- رنگ‌های جدید برای قابلیت‌های بعدی باید با همین پالت هماهنگ باشند؛ از تغییر تم به رنگ غالب دیگر خودداری شود.
- این قانون شامل Header، File Manager، Editor، هر دو Terminal، Right Menu، Live Preview، دکمه‌ها، آیکون‌ها، حالت‌های hover/focus/active و اجزای آینده است.
- تغییر این قانون فقط با درخواست صریح کاربر مجاز است.
- تمام متن‌های قابل مشاهدهٔ رابط کاربری همچنان باید انگلیسی باشند و صفحه LTR باقی بماند.
